第一章：專案概述與系統建置目標
1.1 專案背景與市場法規驅動力
全球極端氣候風險加劇，國際永續發展規範日趨嚴格，包含歐盟碳邊境調整機制 (CBAM)、國際財務報導準則 (IFRS S1/S2)、全球報告倡議組織 (GRI Standards 2021)、氣候相關財務揭露 (TCFD) 及台灣金管會「上市櫃公司永續發展路徑圖」與《氣候變遷因應法》，均強制要求企業必須落實溫室氣體碳盤查（範疇一、二、三）及 ESG 關鍵績效指標之量化管理與資訊揭露。
傳統企業在進行 ESG 管理與碳盤查時，常面臨「各部門 Excel 數據分散難以彙整」、「排放係數版本不一致且缺乏稽核依據」、「無佐證附件保存機制」、「計算公式人工手動運算易出錯」以及「無法即時掌握減碳進度」等痛點。因此，建置一套標準化、自動化且具備審批與軌跡留存的 ESG 永續管理系統刻不容緩。
1.2 系統建置目標
本系統旨在為企業打造一站式 ESG 數據蒐集、碳盤查量化計算、憑證歸檔、審批工作流與報表自動化生成平台，核心目標如下：
1. 碳盤查自動化精準計算：依據 ISO 14064-1:2018 與 GHG Protocol 標準，支援範疇一 (直接排放)、範疇二 (能源間接排放) 及範疇三 (其他間接排放) 之活動數據填報與排放量自動試算 (活動數據 × 排放係數 × GWP)。
2. 跨部門多維度數據收集與工作流：建立標準化 ESG 指標範本（環境 E、社會 S、治理 G），支援各廠區、各部門線上定期填報、附件憑證上傳（發票、電單、檢驗報告）與多級主管簽核流。
3. 係數庫動態管理與版本追溯：內建台灣環保署 (環境部) 碳足跡係數庫、能源局電力排碳係數、IPCC AR5/AR6 GWP 評估數據，並支援自訂自建係數與版本歷史管控。
4. 視覺化 ESG 戰情室與報告書產出：提供即時碳排熱點分析、年度減碳目標追蹤、S/G 指標達成率，並一鍵自動匯出 GRI 指標對應表與 Excel / PDF 報表底稿。

1.4 專案範疇與限制
本專案基於企業內部伺服器 (On-Premise) 或內網私有雲部署模式，採用標準 XAMPP 環境（Apache 網頁伺服器 + MySQL 資料庫 + PHP 核心引擎），確保企業敏感營業數據與碳排放數據不外流，具備高度自主性與安全性，並支援跨部門區域網路 (LAN) 及安全 VPN 存取。
第二章：系統架構與技術棧規格
2.1 系統架構設計 (MVC 架構)
系統採用經典三層式 MVC (Model-View-Controller) 架構，確保系統各組件高度解耦、便於維護與未來模組化擴展：
• 展示層 (View)：基於 HTML5、Bootstrap 5 與 AdminLTE 3 後台樣板，搭配 JavaScript (jQuery, Chart.js, ECharts, SweetAlert2) 提供極佳的響應式 (RWD) 使用者互動體驗與視覺化圖表。
• 業務控制層 (Controller / Service)：由 PHP 8.2 物件導向程式碼構成，負責處理 HTTP 請求、安全防護驗證 (CSRF/XSS)、碳排計算核心演算法、工作流審批狀態機及檔案上傳控制。
• 資料存取層 (Model / DAO)：透過 PHP PDO (PHP Data Objects) 介面進行 MySQL 資料庫連線與 Prepared Statements 參數化查詢，防止 SQL Injection 注入攻擊。

3.2.2 碳排放係數庫管理 (Emission Factor Database)
• 內建係數庫：系統預載台灣環境部 (環保署) 碳足跡係數庫 1.2 版、能源局歷年電力排碳係數 (如 0.495 kg CO2e/度)、IPCC AR5/AR6 之 GWP 數值表。
• 自訂與版本管控：允許企業新增供應商特定自訂係數（如特定化學品或特殊原料），並具備「有效起訖日」與「版本追溯」機制，確保歷史年度盤查數據不因新係數覆蓋而產生偏差。
• 試算引擎公式：碳排放量 (tCO2e) = ∑ [ 活動數據 × 排放係數 × GWP ÷ 1000 ]
3.2.3 水資源與廢棄物污染防制管理
• 水資源管理：自來水用水度數、地下水抽取量、工廠冷卻水回收再利用量、廢水放流量及水質檢測數據 (COD, BOD, SS, 重金屬檢測報告)。
• 廢棄物管理：依環保署代碼分類記錄一般事業廢棄物 (D類)、有害事業廢棄物 (C類)、廢棄物再利用率 (焚化/掩埋/物理處理/回收)，並上傳清運遞送聯單。

3.5 模組五：數據填報、憑證附件與審批工作流模組 (Workflow Engine)
本模組為解決跨廠區、跨部門數據收集混亂之關鍵機制，具備任務派發、線上填報、附件查驗與多層級審批狀態機。
3.5.1 工作流狀態機設計 (State Machine)
• 狀態 1【待填報 (Pending)】：系統依排程（每月初或每季初）自動生成填報任務，並透過 PHPMailer 發信通知各廠區部門負責人。
• 狀態 2【已暫存 (Draft)】：填報人可在線填寫部分數據並暫存，隨時修改，尚未進入簽核。
• 狀態 3【已提交 / 待初審 (Submitted)】：填報人確認數據無誤並強制上傳憑證附件（如無憑證將提示警告），提交給部門一級主管。
• 狀態 4【退回修正 (Rejected)】：審核主管若發現數據異常或憑證模糊，可填寫退回原因退回給填報人，狀態重置並郵件通知補正。
• 狀態 5【初審通過 / 待委員會複核 (Approved Level 1)】：部門主管核准後，流轉至集團 ESG 推動小組進行跨部門橫向複核。
• 狀態 6【最終核准並封存 (Final Approved / Locked)】：ESG 委員會核准後，該筆活動數據即刻納入正式計算引擎，且欄位進入鎖定防篡改狀態。
3.6 模組六：智慧儀表板與報表生成模組 (Dashboard & Reporting)
• ESG 戰情室視覺化：
   - 總碳排放量即時儀表盤（按範疇一、二、三分佈；按廠區分佈；按能源別分佈）。
   - 年度減碳目標對比圖（基準年 vs 目標年 vs 當前累積值，顯示達標百分比與差距警示）。
   - 碳排放強度 (Emission Intensity) 計算：每單位營收碳排放 (tCO2e/百萬元) 及每人均碳排放 (tCO2e/人)。
• 永續報告書底稿與報表自動產出：
   - GRI Content Index 2021 索引對照表自動映射匯出。
   - ISO 14064-1 溫室氣體盤查清冊 Excel 檔案匯出（含 activity data、emission factors、計算公式欄位）。
   - ESG 關鍵績效彙整年度 PDF 報告一鍵生成。

第五章：介面與外部整合設計 (UI/UX & Integration)
5.1 使用者介面 (UI/UX) 設計原則
1. 響應式佈局 (RWD)：基於 Bootstrap 5 柵格系統，保證在桌上型電腦、筆電及平板電腦上均有良好的排版與操作流暢度。
2. 表單輸入防錯與即時驗證：利用 JavaScript / jQuery 進行前端欄位格式檢查（如負數防呆、小數點位數限制、必填欄位提示），後端 PHP 同步實施嚴格二度驗證。
3. 智慧動態聯動：選擇特定排放源時，系統自動下拉匹配該項目對應之單位（如柴油自動帶出公升，電力自動帶出度數），並自動載入有效年份之官方排碳係數與即時預估碳排量。
4. 狀態色標指示：工作流狀態採用直觀色標（草稿-灰色、待審-黃色、通過-綠色、退回-紅色），提升審查效率。
5.2 Excel 範本批量匯入匯出介面
• Excel 匯入模組 (PhpSpreadsheet)：提供標準填報範本下載（含填寫範例與下拉選單約束）。上傳後系統自動進行資料列解析、型態比對、重複性偵測，並將錯誤列詳細反饋給使用者，全部合格後方執行事務寫入 (DB Transaction)。
• 報表匯出介面：支援將盤查清冊、各範疇統計表、GRI 索引表導出為 Excel (.xlsx) 及 PDF 格式。
5.3 郵件通知與自動排程介面
• SMTP 郵件引擎 (PHPMailer)：整合公司內部 Exchange 或外部 SMTP 伺服器，於每月填報日、退件補正、主管審核完成時發送 HTML 格式通知信。
• Windows 排程任務 (Task Scheduler)：設定每月 1 號凌晨 01:00 執行 PHP CLI 腳本 (`php cron_job_monthly_tasks.php`)，自動建立全公司當月填報任務工單。
第六章：非功能性需求與資訊安全規範
6.1 系統效能需求
• 頁面載入速度：常規數據清單與表單頁面載入時間不大於 1.5 秒；5 萬筆以上歷史數據查詢不大於 2.5 秒。

• 並行處理能力：支援至少 100 位使用者同時在線進行表單填報與報表檢視無延遲卡頓。

7.2 XAMPP 環境組態優化建議 (php.ini & my.ini)
為保證系統處理大量碳排數據運算與憑證上傳之順暢，需對 XAMPP 預設配置進行以下微調：
• php.ini 設定：
   - upload_max_filesize = 20M (允許較大之檢驗報告或 PDF 憑證上傳)
   - post_max_size = 25M
   - memory_limit = 256M (確保 PhpSpreadsheet 匯出大型報表記憶體充足)
   - max_execution_time = 300 (延長大型報表產生與批量計算之逾時上限)
   - date.timezone = Asia/Taipei (設定標準台灣時區)
• my.ini (MySQL 配置) 設定：
   - innodb_buffer_pool_size = 512M (提升資料表查詢快取效能)
   - max_connections = 200 (擴充並行連線數上限)
   - character-set-server = utf8mb4、collation-server = utf8mb4_unicode_ci
7.3 安全性加固步驟
1. 修改 MySQL 預設 Root 密碼：於 phpMyAdmin 或 MySQL CLI 中為 root@localhost 設定強密碼，並刪除匿名帳號與測試資料庫 (test)。
2. 建立專屬 DB 帳號：建立名為 esg_admin 且僅對 esg_db 資料庫具有 CRUD 權限之獨立帳戶，禁止應用程式以 root 權限連線。
3. 封鎖 phpMyAdmin 對外存取：修改 httpd-xampp.conf，僅允許本機 127.0.0.1 存取 phpMyAdmin，防止內網未授權登入。
4. 限制 uploads 目錄執行權限：在 uploads/ 目錄建立 .htaccess 寫入 php_flag engine off，徹底防止上傳 PHP 木馬腳本被執行。
